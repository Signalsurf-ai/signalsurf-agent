# Phone

Resolve the requested Person and verified phone endpoint through Records or Conversations; preserve the user's chosen number and human-versus-AI intent. Inspect live capability schemas and sender_infrastructure_query voice_status before effects. Missing number inventory, compliance or budget is not an empty conversation history.

For a human call, use message_send new_call with the exact Project, sender number and destination. Open or return its protected browser continuation so the person can grant microphone access and speak. Preparing a continuation does not prove a call was placed or connected.

For an AI call, use message_send start_call with the exact target and requested purpose under the server's bound confirmation. Report actual accepted/ringing/connected/completed status; reconcile an unknown provider result before retrying. Use message_send end_call for an explicitly requested hangup. Never switch a human call to an AI call without that intent.

For provisioning, use sender_infrastructure_query voice_numbers, voice_quote, voice_setup, voice_purchase and voice_orders as the live schema permits. Show the actual recurring and usage charges before purchase; credentials and protected checkout stay in SignalSurf's continuation. Reads and preparation never authorize buying a number or starting a call.

Read completed history and artifacts through conversations_query search/get. Preserve actor, Workspace and Project boundaries; a call id is not access. Display pending transcription or source errors explicitly rather than inventing content, and do not create a new call to repair missing history.

For incoming callbacks, read sender_infrastructure_query voice_incoming_route on the exact owned number, with the intended assigned owner when choosing a Project. Configure incoming through sender_manage voice_update_number with the number and route revisions. A forward route requires the exact US/Canada forwarding endpoint, assigned history owner, eligible Project and recording consent. Show that preview: saving authorizes future transfers and usage under the Workspace budget/credits. Disabled stops forwarding; omitting incoming preserves it. This route forwards to a phone, not a browser or AI assistant. Read incoming outcomes and artifacts through conversations_query.
