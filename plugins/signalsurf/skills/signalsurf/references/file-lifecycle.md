# Native File deletion

Read this procedure only for an explicitly requested whole-File deletion or its reconciliation.

Native member File deletion follows its declared Workspace lifecycle scope and current resource authority. Historical Project attachment is not an independent deletion requirement. Do not create a Project, Thread or Surfer Run to delete a File, enter an inaccessible old Project, or claim File ownership to bypass a native permission failure. File editor ownership does not grant Workspace Admin. Discover the exact native delete action for the actual resource kind; a missing action in one tool family does not establish that the product has no deletion capability. An explicit human request to delete a resolved File authorizes the exact native MCP member delete invocation: supply a stable operationId, execute under current Workspace role/OAuth checks, and do not request a second conversational yes or add an Always allow setting. Preserve exact target, revision, dependency and protected-resource checks and existing confirmation resumes; internal Surfer/browser and autonomous confirmations remain unchanged. Ordinary Sheet Trash retains rows and owned Enrich for 30-day restore; Listening preserves its collected Sheet. Reuse the same operationId and payload for receipt replay and reconcile unknown outcomes without a new deletion. Read native state and Project Files before reporting cleanup complete. Deleting a List does not delete its backing Records. Report the verified deletion result or actual native blocker. Delegated background execution retains its own Project and File authority.

For a timeout or unknown result, read the synthetic [exact-retry example](examples/exact-retry.md).
