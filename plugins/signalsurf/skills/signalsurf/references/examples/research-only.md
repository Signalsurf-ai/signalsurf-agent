# Research only

**Request:** “Summarize this known LinkedIn profile and its five latest available public posts. Do not save it.”

1. Reuse the supplied profile URL and existing retained evidence. Discover the native `social_get` profile/posts action and its bounded schema. Inspect required context, confirmation and cost before dispatch.
2. Read observed profile/posts evidence; preserve source URLs and retrieval time. A partial result containing three available posts supports three, not an invented five. Separate source facts from inference.
3. Answer in the current host with source attribution and the actual coverage. Do not create a Person, Company, List, Sheet, Enrich binding, Listening or Project Thread for routine research.

**Completion:** actual returned profile/post evidence supports the summary. An empty result means no evidence returned by that attempt, not exhaustive absence or automatic provider failure.

**Unknown result:** inspect the retained result/receipt before paid rediscovery. Reuse the exact operation identity only if its native retry permits it. Stop and report unresolved evidence when reconciliation cannot establish the result. A later request to save the Person starts separately scoped capture with schema/identity checks; Company capture needs verified evidence.
