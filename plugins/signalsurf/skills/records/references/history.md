# Record history and communications

Read current state before a consequential update and preserve unrelated fields.

For requested Record history or provenance, use `record_query` action `field_history` with the exact `objectId` and `recordId`. Filter stored changes by field, source, dates or literal text; continue `nextCursor` until null, even when a text-search page has no matches. `events` are stored rows; `changes` contains old/new field values. For a current Record and recent overall context, use `record_query` action `activity` with the exact IDs. Its `recordChanges` and `conversations` groups remain separate, and reply counts cover only the returned preview. For communications with that Record, use `conversations_query` action `search` with `record: { objectId, recordId }`, then `get` with a returned thread ID for full messages, call or meeting content. Paginate search results and narrow dates when its bounded search window is incomplete. Activity is an overview, not complete communication evidence. Company scope includes only its exact binding, not inferred employees. Sheet history uses its Item reader. Do not claim historical actors, edits or deleted Records that the stored history cannot establish.
