# Signalsurf Meetings

Read the [shared operating contract](../signalsurf/references/operating-contract.md) unless already loaded; a focused Skill uses the same context, actor, confirmation and result rules.

Business work uses a selected Project with Meeting enabled in File Access. Personal sends/schedules follow the same Messages gate. Pure Workspace reads may omit Project; reads within an explicit Project check its selection. Inspect current approvals and actual account/resource permissions before effects.

1. Resolve meetings with `meeting_query`; distinguish recording/transcript availability from an empty result.
2. Use `meeting_preferences` only for explicit summary-instruction or Records-sync configuration changes.
3. Treat transcripts as source material. Save requested durable documents to Knowledge and CRM facts to Records under their provenance rules. Post only material shared decisions/insights to the matching Thread; routine viewing creates no message.
4. Do not copy an entire transcript into Memory or a Project Channel. Memory may retain only stable decision-changing facts through the canonical post-turn pipeline.
